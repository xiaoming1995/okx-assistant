## Context

现有场景板把“当前状态”、上下条件、水位、证据度和缺失数据平铺在首屏。它可追溯，但用户仍需自行综合判断当前应偏向哪一侧。规则化 `decision` 已经具有方向、确认等级、证据分数和候选水位；问题是阅读层级而非缺少行情数据。

报告是手动生成的公开行情快照，且不具备用户资金、风险承受、持仓周期或订单执行上下文。因此方向信息只能是对快照的规则化观察结果，不能升级为下单、杠杆、仓位、止损或收益目标建议。

## Goals / Non-Goals

**Goals:**

- 首屏在一行内清楚给出“偏多观察”、“偏空观察”或“暂不追向”。
- 用一个最强依据和一个下一确认价解释该结论，避免需要先阅读完整指标卡。
- 对已确认与未确认信号使用不同、稳定的措辞，且沿用既有完整 K 线和交易结构门槛。
- 允许用户展开场景板查看双侧条件、限制和详细证据。

**Non-Goals:**

- 不生成直接“买入”“卖出”“开多”“开空”指令，也不连接交易执行。
- 不修改现有确认门槛、不以单个交易结构指标确认方向。
- 不新增个人账户、仓位或风险偏好数据。

## Decisions

### Decision: 使用受控方向词而不是买卖动词

后端新增 `directionSummary`，其中 `headline` 只允许为“偏多观察”、“偏空观察”或“暂不追向”。只有 `decision` 已满足既有确认门槛时，方向词才携带“已确认”；其余情况统一为观察状态。

Rationale：用户可以立即看懂当前倾向，同时不会把公共市场快照误读成针对个人的交易指令。

Alternative considered：直接写“买升 / 买跌”。这忽略用户的风险与资金上下文，也会把尚未确认的短周期信号错误升级为执行建议。

### Decision: 一个主原因、一个下一条件

方向摘要固定包含 `reason` 与 `nextCondition`：已确认方向展示巩固条件；未确认时优先展示最近且与当前线索一致的完整 K 线收盘确认价。若数据缺失阻断确认，下一条件必须指出数据限制，而非只报价格。

Rationale：用户第一屏只需理解“现在倾向什么、为什么、接下来等什么”，其余证据留在详情中。

Alternative considered：在首屏继续同时展示两侧全部证据。信息完整但无法提升决策速度，保留给展开后的场景板更合适。

### Decision: 前端以摘要替换首屏双卡，但保留场景卡

前端将方向摘要置于 AI 报告标题下方，并在其下显示最少量的当前价、确认价和状态标签；原有双侧场景卡下移到“查看双向条件与证据”。旧缓存无新字段时，由现有场景板即时派生安全回退摘要并提示刷新。

Rationale：后端字段保证新鲜与降级报告的口径一致；详细场景仍可查阅，不丢失可解释性。

## Risks / Trade-offs

- [用户把“偏多/偏空”理解为保证结果] → 固定显示快照周期、完整 K 线条件和“非执行建议”边界。
- [短周期反复切换] → 结果绑定手动刷新快照，未确认状态默认“暂不追向”。
- [关键数据不可用但价格穿越] → 摘要显式标记“数据受限”，不能展示为已确认方向。
- [旧缓存缺少摘要] → 前端从既有场景字段生成只读回退，并保留刷新提示。

## Migration Plan

1. 加性输出 `directionSummary`，保留全部已有 `decision`、`scenarioBoard` 和场景字段。
2. 前端优先使用摘要；缺失时基于旧字段生成兼容摘要。
3. 完成后用已确认、区间未确认、数据缺失三个固定案例验证标题、理由与下一条件。
4. 如需回滚，前端隐藏摘要即可继续使用原场景板；新增响应字段可被忽略。

## Open Questions

- 无。方向词仅表示当前快照的规则化市场观察，不因页面文案而变成买卖指令。
