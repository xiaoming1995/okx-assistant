## Context

AI 看行情是一个手动触发、只读的市场快照页面。现有报告已经能显示方向、多周期趋势和展开的场景依据，但面板层、场景层和卡片层同时使用了 `gap`、`margin-top` 与 `margin-bottom`。这些距离叠加后形成不稳定的视觉节奏。手动分析期间，页面只把主按钮改为“分析中”，首次使用者看不到请求在处理，已有报告的用户也不知道画面是否仍是上一份快照。

本变更只涉及 `MarketAiOutlookPanel` 及其样式和静态测试。它不改变 AI 判断、K 线采样、交易结构数据或任何交易执行能力。

## Goals / Non-Goals

**Goals:**

- 为报告建立四级可预测的间距层次：标签、紧凑内容、卡片内容和独立模块。
- 在首次手动分析时显示与最终报告结构相近的骨架，减少空白与布局跳动。
- 在已有报告刷新时保留上一次报告，并明确告知正在更新快照。
- 让状态文本可被辅助技术读取，并在用户偏好减少动态效果时停止动画。

**Non-Goals:**

- 不更改方向结论、置信度、条件确认价或多周期判断规则。
- 不新增行情接口、轮询、自动分析、仓位、下单或投资建议功能。
- 不用虚假的进度百分比表达网络或分析进度。

## Decisions

### 1. 由现有 `loading` 与报告是否存在推导两种加载体验

`loading && !outlook` 表示首次分析；`loading && outlook` 表示刷新已有报告。这样无需在请求生命周期中增加状态机或后端字段，且复用已有的“失败后不清空上一份报告”行为。

备选方案是新增 `phase` 状态并追踪网络、解析和渲染阶段。当前接口不提供可靠阶段信息，展示这类阶段会制造不准确的进度暗示，因此不采用。

### 2. 首次分析使用结构骨架，刷新使用轻量状态条

首次没有可阅读内容时，显示方向区域和三张周期卡片的结构骨架；已有报告时，报告继续可见，只在标题下显示“正在更新行情快照”的状态条，并让刷新图标旋转。两种情况都禁用重复触发按钮。

备选方案是覆盖整页遮罩或在刷新时清空报告。遮罩会妨碍继续阅读，清空则会让用户误以为历史快照失效，因此不采用。

### 3. 将间距归属到容器，避免子元素外边距累加

AI 报告面板使用局部 CSS 变量表达四级间距：4px 标签、8px 紧凑内容、12px 卡片内边距、16px 独立模块。场景面板及其方向、多周期和详情模块以父容器的 `gap` 分隔；原本为分隔而存在的相邻外边距归零。三张周期卡片使用同一网格和相同的内部布局，使其顶部、正文和底部条件对齐。

备选方案是保留现有规则并逐一微调数值。这会持续依赖嵌套外边距的偶然叠加，不利于后续新增模块，因此不采用。

### 4. 加载反馈使用语义状态和低干扰动画

状态条使用 `role="status"` 和 `aria-live="polite"`，骨架不重复朗读整份报告。旋转图标和渐变骨架仅作为处理中的视觉线索；`prefers-reduced-motion: reduce` 下动画关闭。所有文案描述已知事实（正在请求或正在更新），不声明不存在的完成百分比。

## Risks / Trade-offs

- [骨架与最终内容高度不同] → 骨架复用方向与三周期的主结构和相同栅格，避免明显的横向或模块级跳动。
- [刷新耗时较长] → 持续显示上一份报告和“正在更新”状态，而不是让用户面对空白页。
- [统一间距影响窄屏] → 保留现有响应式单列规则，仅收敛同层间距与卡片内部布局。
- [状态提示过多] → 仅在加载期间出现，完成或失败后移除；失败继续复用现有错误提示。

## Migration Plan

这是纯前端、向后兼容的样式和渲染变更。发布后，用户下一次手动分析或刷新即可获得新反馈；不需要数据迁移。若出现视觉回归，可回滚这两个前端文件，原有 API 和分析结果不受影响。

## Open Questions

无。接口没有可靠的分析阶段进度，因此本变更明确不显示百分比进度。
