## Context

AI 看行情使用服务端签发的图表快照，手动生成后展示当前结论、图表依据和条件推演。响应已包含 `suggestion.action`、`condition` 与 `invalidation`，但前端没有把行动倾向作为独立模块呈现。与此同时，`/api/market/stats` 已按合约和周期返回多空人数比、主动买卖量和持仓量；它在交易数据页独立加载，尚未成为 AI 报告证据。

本变更需要在同一份手动 AI 报告中连接这两类公开数据，但不能把短周期统计包装成确定收益或订单指令。统计周期需与所选 K 线相同（可支持）或显式回退为 5m；报告仍以图表快照为技术主证据。

## Goals / Non-Goals

**Goals:**

- 把已存在的行动倾向、条件和失效条件呈现为显著且可解释的“决策参考”。
- 将当前合约的多空人数、主动买卖和持仓变化作为报告内交易结构证据，并展示周期、时间、来源和可用性。
- 用确定性规则识别技术方向与交易结构之间的确认、冲突和缺失，优先提示等待确认。
- 用普通用户可理解的语言说明暂不形成方向与市场总持仓增减，避免将数据缺失误读为零或个人仓位。
- 将交易结构摘要纳入 AI 生成证据与缓存身份，确保一份报告可以回溯其所依据的数据状态。

**Non-Goals:**

- 不使用账户余额、持仓、风险偏好或任何私有资料生成个性化投资建议。
- 不提供具体仓位、杠杆、收益承诺、自动建仓/平仓或订单草稿。
- 不在进入页面、切换合约/周期或实时行情变化时自动生成 AI 报告。
- 不接入当前工程尚未使用的资金费率、盘口深度、清算、大户或跨交易所数据。

## Decisions

### Decision: Render an action reference, not an execution recommendation

新增报告首要模块“决策参考”，复用规范化 `suggestion.action` 并映射为“偏多参考、偏空参考、等待确认、降低关注或继续观察”。模块固定显示：行动倾向、参考置信度、触发/关注条件、失效或重评条件，以及数据质量。它不得显示“立即买入/卖出”“开仓”或仓位数字。

理由：用户需要能回答“目前怎么读”，但系统没有用户风险承受能力，因此行动应是公开数据的条件化解释而非个性化交易指令。

备选方案：继续只显示条件推演。该方案无法暴露后端已经产生的行动倾向，也不能解决用户找不到建议的问题。

### Decision: Build a bounded trading-structure evidence snapshot on the backend

AI 请求在验证图表 `snapshotId` 后，按所选 K 线周期读取已有的市场统计；若该周期不受统计 API 支持，使用明确标识的 5m 回退。后端仅保留每项的最新值、变化/方向、统计周期、更新时间、来源、缓存年龄和告警，并把这些字段同时用于确定性决策说明与 LLM 证据。前端不为同一 AI 报告再发起单独统计请求。

理由：这样使报告的交易结构具备服务端来源、稳定的缓存身份和局部失败回退，避免前端的后加载统计与已生成报告混淆。

备选方案：AI 页独立使用 `useMarketStats`。虽然改动更小，但统计会在报告之外更新，用户无法分辨它是否属于本次 AI 结论。

### Decision: Prefer conflict-aware waiting over forced directional synthesis

交易结构会生成有限的、可解释的观察项：多空账户状态、主动买卖状态、持仓变化。只有当图表方向与至少两项可用结构信号同向时，才标记为“结构确认”；当可用信号相互冲突、数据部分可用或图表为区间时，决策参考必须标为“等待确认”或降低置信度，并解释冲突来源。

理由：多空人数、主动成交和持仓量观察的含义不同，简单汇总成分数会隐藏矛盾并诱发过度交易。

备选方案：给三项统计计算一个不透明情绪分数。它不利于复核，也不能说明为何需要等待。

### Decision: Keep advanced external data explicitly out of this release

资金费率、标记/指数价差、订单簿、清算和大户指标在本变更中不显示为“投资数据”，因为工程尚未建立采集、频率、缓存和降级契约。界面只展示实际已经接入并写入本次报告的字段。

理由：不完整或未经验证的数据比没有数据更容易造成误导。

### Decision: Explain unavailable decision evidence where it is displayed

当报告无法形成方向时，行动标签使用“暂不形成方向”，并直接说明当前仅观察而非买卖信号。持仓变化在报告内称为“市场总持仓增减”，用于说明未平仓合约的总体变化；若不可用，卡片必须说明“暂未获取、不参与本次判断”，并指出缺失不等于零或无人持仓。

理由：原始状态词会让用户将系统的证据不足误读为具体交易建议，或将数据源失败误读为市场数值。

## Risks / Trade-offs

- [交易统计与 K 线的采样频率不同] → 显示统计周期和更新时间；1m K 线使用 5m 统计回退并明确标识。
- [统计源局部失败] → 保留图表报告，给受影响指标单独标记不可用，整体决策参考降为等待确认或数据待确认。
- [LLM 将观察写成确定性指令] → 延续安全文本过滤，且用后端确定性映射限制行动枚举与展示文案。
- [统计刷新导致缓存语义不清] → 将统计来源/时间和关键结构摘要包含在报告缓存键与报告输出中。
- [首屏信息变多] → 决策参考只展示三项结构摘要，历史点位保持在交易数据页面而非复制到 AI 页。

## Migration Plan

1. 扩展后端的 AI 市场证据，读取并归一化当前合约的交易结构快照。
2. 生成并校验冲突感知的决策参考，更新 AI 输出契约与缓存键。
3. 在 AI 页面增加决策参考及紧凑结构证据区，保留现有图表依据、条件推演和只读说明。
4. 增加后端、前端静态与浏览器验证；确认手动触发与数据降级仍可用后部署。
5. 如需回滚，前端忽略新增字段，后端停止附带交易结构证据；现有图表报告与交易数据页不受影响。
