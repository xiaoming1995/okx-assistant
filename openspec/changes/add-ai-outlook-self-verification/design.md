## Context

AI 看行情由用户手动触发；报告同时含模型主图立场、服务端确定性的 15m 价格计划以及自由文本短周期解读。当前缓存只存在内存中，无法跨服务重启保存预测，也没有事后核验。SQLite 与 PostgreSQL 共用 `Database` 门面，后端启动时已有后台循环。

## Goals / Non-Goals

**Goals:** 每次新报告保存可复算的预测样本；到期后自动使用对应周期的完整 K 线核验；展示样本数量和方向命中率；把有限、已核验的样本摘要提供给后续 AI 分析。

**Non-Goals:** 将自由文本强行量化为胜负、模拟真实成交或净收益、自动改写模型权重、把历史命中率当作收益率、自动下单。

## Decisions

### 一个报告生成多个结构化样本

用独立表保存每个可核验判断，按 `report_id` 关联同一次报告。样本类型为 `main_direction`（模型主图立场）和 `price_plan_15m`（服务端方向计划）；中性、无计划及数据不可用也存为 `not_scored`，但不参与命中率。记录预测时的合约、周期、快照、版本、方向、基准完整 K 线收盘价、目标 K 线时间、计划价格和来源。主图方向按相同快照、类型、方向和规则版本去重；新版价格计划另将报价时间及入场、止盈价纳入稳定键，使一次新报价形成新样本，而缓存复用仍不重复计数。

### 仅用未来完整收盘价核验方向

目标是预测基准 K 线之后的下一根完整 K 线。实际收盘价相对基准价格的变化若超过 `max(0.1%, 两个 tick 的比例)`，且方向一致，记为 `hit`；显著反向记为 `miss`；不足门槛记为 `flat`。价格计划另用该 K 线的最高价和最低价记录买卖、止损及止盈参考价是否落在价格区间内；这只是触价观察，无法判断触价先后，也不视为成交或收益。核验规则及阈值随记录冻结，后续代码变化不重写旧样本。

若价格计划首次读取的独立 15 分钟 K 线过期或仅能取得缓存，服务端再读取同一周期一次；仅当重试结果本身完整且新鲜时使用，不能从主图其他周期推导价格计划。

### 后台独立重试，不猜测缺失行情

启动一个每分钟检查到期样本的守护任务，批量获取相应合约与周期的 K 线；只有目标时间戳完全匹配且 `confirm=1` 才结算。上游暂时失败时保留 `pending`，超过三个目标周期仍缺数据则标为 `insufficient_data`，不纳入命中率。数据库更新只从 `pending` 转为终态，避免多次后台检查重复结算。读接口不触发新的行情请求。

价格计划另读取报告生成后的完整 1 分钟 K 线。新版报价入场计划冻结分析时的买一／卖一报价与报价时间，无须等待后续再次触及该报价；核验预测止盈价是否到达，以及在止损先出现或同分钟先后未知的情况下能否确认有效目标路径。旧版突破入场计划继续核验先到入场价、后到止盈价。报告生成所在分钟的高低价可能发生在报告之前，故不计入；缺少完整分钟数据时给出数据不足或先后未知，不用 15 分钟整根触价推断顺序。这仍只是价格路径观察，不证明委托成交。已结算旧样本维持原核验结果，页面标记其旧口径。

### 有限的历史反馈

下一份报告只接收同合约、同提示词版本的已核验统计与最多三个结构化例子；数量不足五个有效方向样本时不展示百分比。模型可以用它校准不确定性措辞，但不能修改服务端价格计划、声称完成训练或承诺未来表现。缓存键包含样本摘要的版本指纹。页面通过只读 API 展示最近样本、待核验数量及有效样本分母。报告顶部常显最近一次核验摘要，展开后显示完整记录；摘要需区分方向符合与买卖参考价是否触及，避免把触价或方向符合误读为成交。

另设“市场 → 预测记录”独立页面，读取跨合约样本的分页列表，并按合约、样本类型和结果筛选。15分钟价格计划冻结有效截止时间和入场条件；列表直接写出报告生成至截止的入场观察期、做多买入或做空卖出的参考价，以及在截止前触价时止盈和止损的退出参考价。退出的实际时间不可预知；到期未触价只能重新评估，不能编造届时成交价。列表还显示方向核验目标 K 线起止、方向结果、实际收盘和三个参考价的触及情况；展开后展示报告编号与摘要。目标 K 线在报告生成时已开始，或报告生成时已收盘而不计分时，列表应明确提示时间局限或不计分原因。该页面只读；不会把方向符合或触价显示为成交收益。

报告和记录页的主阅读顺序为预测生成时间、入场观察开始与截止、显著的买入或卖出参考价、条件止盈/止损价、后续方向与触价核验。报告当前样本的核验摘要常显；历史记录的同一结果紧贴原计划。记录页默认筛选有买卖价的 15分钟价格计划，用户可取消筛选查看无价格样本或改看主图方向。无合格计划时明确显示没有买卖价，不把重评价阈值冒充入场价。

核验后另计算“参考价到目标收盘的理论价差”：做多为 `(目标收盘价 - 冻结入场参考价) / 冻结入场参考价 × 100%`，做空取相反数，保留两位小数。核验记录保存该派生值和计算口径；旧的完整样本由冻结入场价和已保存的目标收盘价按同一公式补算。待核验、不计分、数据不足或价格无效时不提供数值。新版计划先显示分析时的报价和后续止盈到价结果；旧版计划显示入场触价结果。两种计划都无法证明成交，理论价差只作为价格对照，不称为实际收益率。该值未扣手续费、资金费和滑点，不进入方向命中率或真实收益统计。

新版计划状态为 `watch` 表示报价价差偏宽，样本冻结 `priceConditionMet=false`。旧版计划的 `watch` 仍按当时的突破条件解释；旧记录缺少该字段时只说明条件细节未知。预计入场价和止盈止损价都不能展示成可立即执行的连续步骤。记录页顶部的主状态对新版显示“分析时报价已记录，成交未证实”，对旧版显示入场是否触及；方向符合仅标明基准收盘到目标收盘的行情方向，不能代替成交结果。

## Risks / Trade-offs

- [方向命中不等于交易盈利] → 页面将指标称为“方向核验”，明确不计成交、手续费、资金费和滑点。
- [同一快照重复分析造成相关样本] → 稳定键去重，并展示有效样本分母。
- [上游行情延迟或断档] → 严格按时间戳和完整标识结算，缺数据单独计数。
- [反馈导致过拟合或放大旧版本表现] → 只给模型少量同版本的结构化历史和明确约束。

## Migration Plan

服务启动时在 SQLite 与 PostgreSQL 以 `CREATE TABLE IF NOT EXISTS` 建表；新记录从上线后开始，不从旧报告或历史行情补造预测。回滚可停止后台任务和读接口，保留历史样本表待后续恢复。

## Open Questions

无。首版只核验可确定方向的两类判断；自由文本预测原文作为报告上下文保存，但不进入方向命中率。
