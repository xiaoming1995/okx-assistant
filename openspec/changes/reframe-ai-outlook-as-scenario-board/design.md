## Context

AI 看行情同时保留 LLM 的 `overall.confidence`、规则化 `decision.confidence`、图表结论、交易结构和条件水位。LLM 总览分数可高于规则化未确认结论的上限，前端又将两者都标为“证据充分度”，形成相互矛盾的阅读体验。条件水位和缺失证据虽然已存在，但位于明细之后，无法先回答“现在是什么状态、下一步看什么”。

报告必须维持手动刷新、快照可追溯和只读公开行情属性；不能生成订单、仓位、杠杆、止盈止损或个人化投资建议。

## Goals / Non-Goals

**Goals:**

- 首屏给出唯一、可追溯的场景证据度和当前市场状态。
- 将当前价格位置、上/下条件确认、缺失证据和失效条件编排为单一阅读闭环。
- 将“数据未获取”从中性指标提升为场景无法确认的显式限制。
- 保留 LLM 文字总结，但不允许其覆盖确定性规则结论或冒充证据度。

**Non-Goals:**

- 不降低“图表方向加至少两项同向完整交易结构”的确认门槛。
- 不输出成交建议、仓位、杠杆、止盈止损、收益目标或个人化投资意见。
- 不增加用户账户、订单簿以外的新外部数据源或自动提醒。

## Decisions

### Decision: 规则化场景证据度是唯一的决策分数

后端将 `decision.confidence` 命名并输出为场景证据度，前端首屏只使用该值。LLM `overall.confidence` 保留在次级“AI 文字解读”中，改名为模型叙述参考，不与规则分数同屏比较。

Rationale：同一数值标签必须有同一计算口径，避免 58% 与 45% 同时出现却无从解释。

Alternative considered：让两项分数同时显示并增加说明。用户仍需先理解系统内部结构，无法提高首屏决策效率。

### Decision: 场景板以状态而非建议作为主语

每一报告均输出 `marketState` 与两个候选场景。当前状态说明价格是否位于观察区、距上下确认线的价格距离及当前最强的可用方向线索；候选场景只在完整周期 K 线收盘、量能和所需交易结构同时满足时才进入“已具备确认条件”。

Rationale：将可核对的市场状态和条件前置，而不将条件价误读为立即成交价。

Alternative considered：直接输出“做多/做空建议”。这会超出公共快照的证据范围，也不能适配用户的资金、风险承受和持有周期。

### Decision: 数据缺失阻断完整场景，并显示影响

每个候选场景都从同一证据缺口生成“满足项、缺失项、不可用项”。当需要的关键交易结构数据缺失时，场景状态为 `limited`，说明即使价格条件达成也只能继续观察、不能升级为完整确认。

Rationale：把“缺数据”转化为用户可理解的限制，而不是与普通中性指标混排。

### Decision: 首屏与明细分层

首屏只渲染场景状态、价格位置、两个候选场景和数据限制。阈值表、逐项缺口、AI 总结和来源归入可展开的“证据详情”。旧缓存缺少场景字段时，前端回退到既有结论和条件确认价，并提示刷新后获得完整场景板。

## Risks / Trade-offs

- [条件场景被误读为交易指令] → 在每个价格和状态旁明确“完整 K 线收盘条件，非成交建议”，不出现仓位或收益语言。
- [短周期噪音造成状态频繁变化] → 所有结果绑定报告快照，只能手动刷新更新。
- [结构数据缺失导致页面显得保守] → 明确展示缺失数据的影响，同时保留已观察到的单侧线索。
- [LLM 输出不稳定] → LLM 只能提供次级文字，不参与场景状态与证据度计算。

## Migration Plan

1. 加性扩展 AI outlook 响应，生成场景板字段并保留现有 `decision` 与 `observationLevels`。
2. 前端优先渲染场景板；旧缓存采用兼容回退。
3. 验证一致性：首屏不再使用 LLM 总览分数作为证据充分度，且每个场景包含价格、证据和失效条件。
4. 若需回滚，隐藏新场景板并恢复原有决策参考区域；后端新增字段可忽略。
