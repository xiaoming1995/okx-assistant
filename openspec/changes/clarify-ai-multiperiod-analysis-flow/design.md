## Context

AI 看行情的后端已经在每次手动报告请求中分别读取固定的 15 分钟、1 小时和日线 K 线，并将 `multiTimeframeTrend` 返回给前端。页面同时提供 `1m / 5m / 15m / 1H / 4H / 1D` 控件作为当前主图 K 线周期；切换它会清除现有报告，确保主结论对应新快照。

当前首次态仅称“当前图表待分析”，周期控件没有可见的主图角色说明，而固定三周期卡仅在报告成功后渲染。用户无法从首次态预期一次分析的覆盖范围，也会将可切换的主图周期误认为必须逐一查询的分析周期。

该变更只调整前端阅读合同，必须遵循项目的简洁工具型风格、4px 间距网格、中文可理解状态、保留数据的刷新反馈和窄屏自然文档流。后端没有逐周期流式进度合同，界面不得编造单项完成状态。

## Goals / Non-Goals

**Goals:**

- 在周期控件附近明确其为“主图观察周期”，并说明它决定本次报告主结论，切换后需要重新分析。
- 让用户在点击前就看见固定的 `15分钟 / 1小时 / 日线` 自动读取范围，而不是在报告完成后才发现。
- 让首次态、初次加载、已有报告刷新与完成态使用一致的“一次分析、三个独立周期”语言。
- 保持现有一次手动触发、只读边界、缓存/错误语义和报告中的三张多周期卡。

**Non-Goals:**

- 不变更 `POST /api/market/ai-outlook` 请求或响应，不变更多周期取数、缓存、LLM 提示词或报告结论。
- 不将固定三周期变为可单独点击、自动轮询或独立 AI 请求的控件。
- 不显示没有真实后端依据的“15分钟已完成、1小时读取中”等逐项进度。
- 不新增下单、仓位、收益预测、个性化投资建议或交易自动化。

## Decisions

### 以主图说明与固定周期概览并列，消除控件语义冲突

在现有 K 线控件附近添加短文本“主图观察周期”，并以辅助说明解释其影响本次主结论。首次态在主操作附近渲染三个紧凑、非交互的固定周期项：`15分钟`、`1小时`、`日线`，统一显示“本次自动读取”或“待分析”。

这样保留用户选择主结论观察尺度的能力，同时提前展示报告的稳定三周期合同。备选方案是将说明仅加入按钮 tooltip 或加载文案；这仍要求用户先触发或悬停才能理解，不能解决首屏误解。

### 用真实可知的整体加载状态，不伪造单周期进度

点击后显示“正在一次性读取 15分钟、1小时和日线的独立 K线快照”，并将固定周期概览切换到统一的“读取中”状态。报告成功后继续使用后端返回的每周期可用性、依据、确认条件和数据待获取提示。

备选方案是前端按三项模拟进度或拆分请求；前者不可信，后者会改变既有请求、缓存和手动分析边界，因此不采用。

### 将多周期结果保持在主结论之后，并让状态概览在窄屏可扫描

报告完成后，现有多周期趋势区域仍紧随主方向结论；首次态和加载态的周期概览采用同一顺序与短标签。窄屏改为自然换行或纵向布局，主操作与状态说明不得被周期控件挤出可见区域。

备选方案是将三个固定周期重新做成可切换页签；它会再次暗示用户需要逐项操作，也会让跨周期同向/分歧的阅读更困难。

## Risks / Trade-offs

- [增加首屏说明会降低一点紧凑度] → 使用辅助文字与三个轻量状态项，不增加嵌套卡片或新的视觉体系。
- [用户误将“待分析”视为数据缺失] → 文案必须是“本次自动读取，开始分析后生成”，与报告中的真实“数据待获取”区分。
- [切换主图周期仍会清空报告] → 在控件附近提前说明“切换后需重新分析”，并保留既有手动触发语义。
- [后端某固定周期不可用] → 仅在报告结果中使用后端返回的真实“数据待获取”状态，不以其他周期补写结论。

## Migration Plan

1. 修改 AI 看行情页面的可见文案和状态结构，复用既有周期、加载和报告组件样式。
2. 补齐静态测试，并在桌面与窄屏核验首次、加载、刷新、完成、禁用与键盘焦点状态。
3. 发布后无数据迁移或 API 兼容性风险；如需回滚，只移除新增前端说明与状态概览，既有报告与后端合同保持不变。
