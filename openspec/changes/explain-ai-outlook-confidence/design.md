## Context

当前 AI 行情页面同时显示总体置信度、决策参考置信度和“数据完整”标签。前者在指标降级时由后端给出保守值，后者只描述交易结构字段是否可取得；页面没有把这两层语义并列解释，导致用户把数据可用性误认为方向可靠性。

本变更不重算市场观点。它为每一份手动生成报告附加一个基于已有响应字段的解释快照，并在决策参考内紧凑呈现。既有报告的安全限制、图表快照归属和缓存语义必须保留。

## Goals / Non-Goals

**Goals:**

- 让用户可从页面直接读出置信度的来源、证据确认状态和数据可用性之间的区别。
- 在指标降级时显示不暴露密钥、供应商内部细节或冗长异常信息的原因说明。
- 让每项交易结构证据展示当前值、阈值解释和本次是否参与方向确认。
- 复用现有确定性阈值和决策规则，确保说明与实际判断一致。

**Non-Goals:**

- 不改动 35%、45% 或 LLM 返回置信度的计算方式。
- 不将解释卡做成预测概率、交易建议、入场价、止损、仓位或杠杆工具。
- 不在页面加载、切换周期或实时数据更新时自动触发新的 AI 分析。

## Decisions

### Decision: Return a bounded confidence-explanation payload from the server

后端从报告 `source`、基础置信度、决策 assessment、交易结构 quality 与现有结构项构造 `confidenceExplanation`。它含来源状态、简短原因、确认门槛、最多三项证据条目和是否参与方向确认。

理由：说明必须绑定本次图表快照和同一份报告，不能由前端根据可能已刷新的市场数据重新猜测。

备选方案：仅在前端写固定帮助文案。它无法说明本次是否发生 LLM 降级或哪些项目实际未形成方向。

### Decision: Separate availability from confirmation in the UI

将 `dataQuality` 显示为“交易数据已获取 / 部分可用 / 待确认”，并在其旁独立显示“方向确认状态”。置信度附近增加“为何是此置信度”紧凑依据区：第一行说明来源与基础值，第二行列出图表方向及交易结构已确认/未确认的条目。

理由：完整的输入字段并不代表同向证据或可靠预测，两个概念必须同屏可分辨。

备选方案：把说明藏在 tooltip。它不满足用户首屏理解需求，也不利于截图或窄屏阅读。

### Decision: Sanitize fallback cause before returning it to the browser

指标降级原因以稳定枚举展示：`LLM 未启用`、`AI 分析不可用，已回退至指标解读`、`市场或宏观数据存在提示`。异常详情仅保留在服务端日志，不进入用户报告。

理由：既能解释降级，也不会泄露连接、认证或供应商错误细节。

## Risks / Trade-offs

- [页面信息增加] → 依据区只显示当前结论相关的三项，完整原始统计仍留在交易数据页。
- [LLM 与规则置信度含义不同] → 标明“参考程度，不是涨跌概率”，并显示来源状态。
- [缓存报告的解释过期] → 解释随报告缓存返回并标示报告生成/缓存状态，不重新混入实时指标。

## Migration Plan

1. 在后端响应构造并为回退/LLM/证据不足场景测试解释快照。
2. 扩展前端类型、文案与紧凑布局，保留缺字段时的兼容呈现。
3. 运行聚焦测试、生产构建、OpenSpec 校验与手动页面检查。
4. 如需回滚，前端忽略新增字段；原有置信度与决策参考不受影响。
