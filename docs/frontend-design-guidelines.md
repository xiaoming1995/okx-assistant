# 前端设计规范

> **适用范围**：`frontend/` 下所有用户可见的页面、组件、样式与交互。
>
> **定位**：本项目采用**简洁工具型风格**。界面应克制、清晰、可靠、低饱和且便于快速扫读；服务于行情、账户、交易和自动化任务，不采用重装饰的金融大屏或营销页风格。

## 1. 使用规则

- 修改前端前必须先阅读本规范，并以它为默认设计基线。
- 新界面优先复用已有基础令牌和通用组件模式；不得为局部页面另起一套颜色、圆角、间距或交互语言。
- 规范与业务需求冲突时，以业务安全、可访问性和信息准确性优先；需要偏离本规范时，应在对应变更中说明原因，并同步更新本文件。
- 前端验收应至少覆盖桌面、窄屏、加载、空状态、错误或缓存状态、键盘焦点以及禁用状态中与改动相关的部分。

## 2. 视觉原则

1. **内容优先**：用户首先看见关键价格、仓位、风险、状态和下一步操作，而非装饰。
2. **一处一重点**：一个卡片或区域只承担一个主任务；次要说明不抢占标题与关键数值的层级。
3. **状态可信**：实时、缓存、待补齐、失败、风险等状态必须明确说明影响范围和可执行的下一步。
4. **克制反馈**：交互需要即时可感知，但不应造成页面跳动、过度动画或视觉噪声。
5. **同类同形**：同类页面头、卡片、按钮、标签、表格、空状态使用一致的结构和语义。

## 3. 间距、尺寸与布局

### 3.1 间距令牌

使用 4px 网格；新样式应从下列值中选择，避免新增 `5px`、`7px`、`9px`、`10px`、`14px` 之类的任意间距。

| 名称 | 值 | 用途 |
| --- | ---: | --- |
| `space-1` | 4px | 标签和数值、图标和文案的微间距 |
| `space-2` | 8px | 紧凑控件组、表格行、卡片内紧凑区块 |
| `space-3` | 12px | 标准卡片内边距、字段之间 |
| `space-4` | 16px | 页面内边距、普通模块之间 |
| `space-5` | 24px | 独立章节、页面主区块之间 |
| `space-6` | 32px | 大屏留白、重要分组之间 |
| `space-7` | 48px | 空状态或页面级强调区域 |

边框宽度、1–2px 的视觉微调、图标描边等非布局值可以例外，但必须有明确目的。

### 3.2 密度

- **紧凑密度**：合约栏、交易表单、工具栏、数据表格。使用 `8–12px` 内边距与 `28–34px` 控件高度。
- **标准密度**：行情摘要、AI 看行情、账户概览、风险说明。使用 `16px` 内边距与 `16–24px` 模块间距。
- 同一内容区域不混用两种密度；主工作台与左侧工具栏这类明确分层除外。

### 3.3 页面骨架

页面按以下顺序组织，避免无目的地嵌套卡片：

```text
PageHeader（标题、说明、关键操作、状态）
├─ PageSummary（可选；只展示不与正文重复的关键指标）
├─ PageContent（图表、表格、表单或工作台）
└─ PageFeedback（加载、缓存、错误、空状态）
```

- 标准页面内边距：窄屏 16px；桌面根据工作台密度取 16px 或 24px。
- 卡片之间：16px；独立大区块：24px。
- 表格行优先使用分隔线和悬浮底色；不把每一行做成独立卡片。
- 不用纯视觉空白隐藏信息层级；重要状态应有文本说明。

### 3.4 响应式

- **1201px 及以上**：可使用左侧合约栏与主工作区并排布局；合约栏折叠只改变布局，不丢失当前合约和筛选上下文。
- **768–1200px**：工作台改为纵向流程，先选择合约再阅读内容；表格允许清晰的横向滚动。
- **767px 及以下**：页面头纵向排列，筛选和周期控件可横向滚动，关键指标默认两列；核心操作和状态不得因窄屏而隐藏。
- 图表、AI 报告和交易表单不得依赖固定视口高度；窄屏应恢复为自然文档流。

## 4. 表面、颜色与排版

### 4.1 表面与圆角

- 页面背景为浅灰白；普通内容表面为白色。
- 一个页面最多使用两层普通表面：页面背景和卡片；下拉菜单、弹层是唯一可使用第三层表面的场景。
- 圆角统一为 8px；胶囊标签使用完整圆角。
- 普通卡片用细边框区分。阴影仅用于轻微层级提示；浮层可以使用较强阴影。
- 不在普通业务卡片中使用大面积渐变、纹理、发光效果或重阴影。

### 4.2 颜色语义

| 语义 | 颜色 | 文字必须明确为 |
| --- | --- | --- |
| 上涨、盈利、已连接、已启用、正常 | 绿色 | 上涨、盈利、实时、正常、已启用 |
| 下跌、亏损、错误、危险操作 | 红色 | 下跌、亏损、失败、高风险、停止 |
| 缓存、待确认、数据待补齐 | 琥珀色 | 缓存、待确认、待补齐、需检查 |
| 未选中、不可用、历史信息 | 中性灰 | 暂无、未配置、已归档、历史 |

- 状态不能只用红绿表达，必须同时提供文字、图标或可读标签。
- 品牌绿色不用于所有按钮；它只表示正向业务状态或明确的次级操作。
- 红色保留给负向结果、危险操作和卖出方向；不要用于普通提醒。

### 4.3 文字与数据

**字族**

界面西文统一使用 **IBM Plex Sans**，数值、合约代码、时间与代码类文本使用 **IBM Plex Mono**；中文走系统中文字族（PingFang SC / 苹方、Hiragino Sans GB、微软雅黑、Noto Sans CJK SC），不打包中文字体。全局令牌为 `--font-ui` 与 `--font-num`；Mantine 主题的 `fontFamily`、`fontFamilyMonospace`、`headings.fontFamily` 必须与这两个令牌一致，避免原生样式与组件出现两套字族。

选择同源 Sans/Mono 是功能性判断：两者字宽咬合，订单簿与合约账本式的数字列才能纵向对齐，而不是为了更换皮肤。

字体以**自托管拉丁子集**提供（`frontend/public/fonts/`，`font-display: swap`），运行时不依赖外部字体 CDN。离线或加载失败时按回退链落到 Inter / 系统字族，界面可用性与数据可读性不受影响；不得为了字体效果引入运行时外网依赖。

**字阶**

| 层级 | 字号 | 字重 | 用途 |
| --- | ---: | --- | --- |
| 展示级 | 48px（`--type-display`） | 700 | 每个页面唯一的主数值（当前合约最新价或该页主指标） |
| 页面标题 | 20px | 700–800 | 页面头 |
| 模块标题 | 15–16px | 700–800 | 卡片与分节标题 |
| 正文与表格 | 13px | 400–600 | 正文、表格、控件 |
| 辅助信息 | 12px | 400–600 | 说明、时间戳、单位 |

- 一个页面最多一个展示级数字；不得用于标题、卡片或次要指标。窄屏按容器宽度降级（当前市场概况页降到 28px），不新增第二处展示级。**不得为了放大数字而改动数据列布局**：容器放不下时保留原字号，避免 `text-overflow` 把价格截断。
- 价格、百分比、时间、数量、盈亏使用等宽数字（`font-variant-numeric: tabular-nums`）。**`--font-num` 只用于主数值**（展示级主数字、当前合约最新价与涨跌幅、关键指标数值）与代码类文本；其余辅助数值保持 Sans 比例字体，避免整页变成等宽噪声。Mono 是层级标记，不是全局皮肤。
- 合约代码要便于扫描；名称用于识别。长文本截断时保留完整文本的可访问方式，例如 `title` 或展开查看。

## 5. 组件规范

### 5.1 按钮与控件

| 类型 | 高度 | 使用范围 |
| --- | ---: | --- |
| 紧凑控件 | 28px | 周期、筛选、行内操作 |
| 标准控件 | 34px | 搜索、普通页面操作、次按钮 |
| 主操作 | 40px | 开始扫描、保存并启用、提交等推进当前任务的操作 |

- 一个可见区域最多一个主按钮；主按钮表示推进当前任务。
- 次按钮用于返回、查看、刷新、编辑或辅助跳转。
- 危险按钮用于关闭仓位、停止、删除、撤销等高风险或不可逆操作。
- 图标按钮与同组控件高度一致，点击热区不小于 28px，图标不小于 16px。
- 全站功能图标统一使用 `@phosphor-icons/react` 的常规线性图标，放在 Mantine 的按钮、页签、输入框或 `ThemeIcon` 等现有组件内；同一状态可通过填充权重区分，不混用第二套功能图标。图标尺寸沿用所在控件的既有密度，纯装饰图标对读屏隐藏，只有图标的按钮必须保留可读名称。
- 同一按钮组中的控件必须对齐高度、间距和语义。
- 禁用状态必须降低视觉强调，并在必要时说明禁用原因。

### 5.2 卡片、标签与表格

- 卡片只分为基础卡片、语义强调卡片和浮层卡片三类。
- 状态标签保持小型、低饱和；不要让标签挤占页面标题区。
- 可点击卡片在 hover 时优先改变边框和背景，避免所有卡片同时使用悬浮阴影。
- 选择状态采用浅语义底色与边框或左侧标记；不能只改变文字颜色。
- 空状态应说明原因，并在有合理下一步时提供一个对应操作。

## 6. 交互与异步反馈

### 6.1 微交互

- hover 的背景、边框、阴影过渡为 120–160ms。
- 按下反馈为 80–120ms，可轻微降低阴影或下移 1px；不使用夸张缩放和弹跳。
- 展开、收起、切换菜单使用短过渡，不得造成周围内容明显位移。
- 所有动效必须兼容 `prefers-reduced-motion: reduce`。

### 6.2 加载、缓存、错误与空状态

- 首次加载使用对应区域的骨架屏或加载态，而不是无说明的整页空白。
- 已有完整数据时，后台刷新保留旧数据，并在标题或状态区显示“更新中”。
- 有缓存时优先显示缓存数据，并说明缓存与新鲜度；无完整数据时才显示不可用状态。
- 错误信息使用中文，说明受影响区域和可执行恢复方式；不要把上游原始英文错误直接暴露给用户。
- 异步提交在按钮内显示进行状态并阻止重复点击；成功、失败都应给出明确反馈。

### 6.3 可访问性

- hover 必须有键盘焦点的等价反馈，使用清晰的 `:focus-visible` 焦点环。
- 可切换按钮使用合适的 `aria-pressed`；折叠项使用 `aria-expanded`；页签使用 `tablist`、`tab` 和 `tabpanel` 语义。
- 重要状态更新使用适当的 `aria-live`，但不频繁打断读屏用户。
- 图标按钮必须有可读的 `aria-label`。

## 7. 前端改动检查清单

在提交前逐项确认：

- [ ] 新增间距、圆角、颜色、阴影和控件尺寸均来自本规范或已有全局令牌。
- [ ] 页面只保留明确的主操作，不让次要按钮抢占层级。
- [ ] 盈亏、涨跌、连接、缓存、风险状态都有文字与颜色双重表达。
- [ ] 初始加载、后台刷新、空状态、错误或缓存状态符合本规范。
- [ ] 桌面与窄屏下内容、状态和核心操作都可见、可操作。
- [ ] 鼠标 hover、键盘焦点、选中、禁用和加载状态都有一致反馈。
- [ ] 未引入不必要的动画、渐变、重阴影或孤立的局部视觉体系。

## 8. 演进方式

本规范是后续前端改动的基线，不要求一次重写既有样式。收敛顺序为：

1. 全局令牌：间距、字号、层级、过渡与断点。
2. 通用模式：页面头、卡片、按钮、筛选、状态标签、反馈状态。
3. 高频页面：行情图表、AI 看行情、交易、自动化总览、持仓。版式收敛以 3.3 的账本式目标态为对照，逐页进行，不做单页试点式偏离。**进度（2026-11-17）：5 个高频页面已全部迁移完成**（行情图表、AI 看行情、交易、自动化总览、持仓），每页一个独立 scoped CSS 区块并单独通过三档验证；本步骤结束，后续按第 4 节处理长尾页面。
4. 长尾页面：时间线、公告、设置、用量与详情页。**进度（2026-11-17）：5 类长尾页面已全部迁移完成**（时间线、公告、AI 配置 / 设置、AI 用量、信号详情），每类一个独立 scoped CSS 区块并单独通过三档验证；本步骤结束，第 8 节四步收敛全部完成。清单外的功能型页面按 3.3 的边界说明保留原骨架。
5. 默认落地页：合约雷达（2026-11-17 用户追加）。**进度：已完成**。四步收敛后首页仍停在未迁移的雷达页，按 3.3 的整站级主张补做；单独一个 scoped CSS 区块并单独通过三档验证，**不改默认路由、不动 `main.tsx`**。理由与保留项见 3.3 第 5 步。

每次变更都应让相关区域更接近本规范，而不是为了局部效果重新引入新的视觉语言。
